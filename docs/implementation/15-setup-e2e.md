# 実装書(15): セットアップ手順・E2E検証

- **依存**: 01〜14 すべて
- **対象**: コードではなく手順とチェックリスト(実施結果は本ファイルに追記してよい)

## 1. Notion側セットアップ

1. Notion Integrationを作成し、**Internal Integration Token** を控える。
2. `docs/notion-schema.md` の通りに3つのDBを作成する:
   - 在庫DB(Inventory): 品名(Title)/在庫あり(Checkbox)/カテゴリ(Select)/写真(Files & media)/購入先(Multi-select)/保管場所(Select)/賞味期限(Date)/購入履歴(Relation→購入履歴DB)/最終購入日(Rollup: 購入履歴→購入日→Latest date もしくは Max)/更新者(Relation→ユーザーDB)
   - ユーザーDB(Users): 表示名(Title)/LINE User ID(Text)/ステータス(Select: 有効・無効)/登録日(Date)
   - 購入履歴DB(PurchaseHistory): 名前(Title)/対象品目(Relation→在庫DB)/購入日(Date)/購入先(Select)/記録者(Relation→ユーザーDB)
3. **3つのDBすべてをIntegrationに共有**(Connections に追加)する。忘れると404になる。
4. 各DBのIDをURLから控える(`notion.so/<workspace>/<DB_ID>?v=...` の32桁)。
5. **プロパティ名がコードの `NOTION_PROPS` と完全一致していることを確認**(全角/半角・スペースに注意)。
6. 在庫DBにテストデータを2〜3件入れる。
7. `docs/notion-schema.md` の「確定後に記載する項目」にDB IDを記入する。

### 検証ポイント(未確定事項の解消)

## 2. LINE側セットアップ

1. LINE Developersコンソールで Messaging APIチャネルを作成(既存の公式アカウントがあれば流用)。
2. **チャネルアクセストークン(長期)** と **チャネルシークレット** を控える。
3. 応答設定: あいさつメッセージOFF・応答メッセージOFF・Webhook ON。

## 3. GASデプロイ

1. `npm install` → `npx clasp login`。
2. GASプロジェクトを作成し `.clasp.json` に `scriptId` を設定(`.clasp.json` はgit管理外)。
3. `npm run push` でソース反映。
4. スクリプトプロパティを設定:

| キー | 値 |
| --- | --- |
| `LINE_CHANNEL_ACCESS_TOKEN` | LINEチャネルアクセストークン |
| `LINE_CHANNEL_SECRET` | LINEチャネルシークレット |
| `NOTION_TOKEN` | Notion Integration Token |
| `NOTION_INVENTORY_DB_ID` | 在庫DBのID |
| `NOTION_USERS_DB_ID` | ユーザーDBのID |
| `NOTION_PURCHASES_DB_ID` | 購入履歴DBのID |
| `RICHMENU_IMAGE_FILE_ID` | リッチメニュー画像のDriveファイルID |

5. 「デプロイ」→「ウェブアプリ」: 実行ユーザー=自分 / アクセス=全員(匿名)。URLを控える。
6. LINE DevelopersのWebhook URLに設定し「検証」ボタンで疎通確認 → 200。
7. `setupRichMenu()` を実行(実装書14)。

> 注意: コード更新後は `clasp push` だけでなく、**デプロイの更新**(同じデプロイIDの新バージョン発行)が必要。URLが変わらないよう「デプロイを管理」から編集すること。

## 4. E2Eチェックリスト

前提: LINEアカウント2つ(A=自分、B=家族)でBotを友だち追加済み。

| # | 操作(Aの端末) | 期待結果 |
| --- | --- | --- |
| 1 | Botを友だち追加 | あいさつが返る。ユーザーDBに「有効」で登録される |
| 2 | リッチメニュー「在庫一覧」 | 全品目がFlexで表示。✅/❌が正しい |
| 3 | 「新規 トイレットペーパー」 | 登録完了+品目カード+写真の案内 |
| 4 | 続けて写真を送る | 「写真を登録しました」。Notionにファイルが付き、一覧にサムネイル |
| 5 | 「新規 トイレットペーパー」(再) | 「すでに登録されています」 |
| 6 | 「なくなった トイレットペーパー」 | 在庫切れ確認が返る。**Bの端末に通知が届く**。Aには通知が来ない |
| 7 | リッチメニュー「不足一覧」 | トイレットペーパーだけが表示される |
| 8 | 「なくなった トイレットペーパー」(再) | 「すでに在庫切れです」。通知は飛ばない |
| 9 | リッチメニュー「買った」→ 品目タップ | 在庫ありに戻る+「購入履歴に記録しました」 |
| 10 | 「履歴 トイレットペーパー」 | 今日の日付の履歴が出る。Notionの最終購入日も今日になる |
| 11 | 「編集 トイレットペーパー」→ 購入先を変える →「スーパー / Amazon」送信 | Notionの購入先Multi-selectに2つ付く |
| 12 | 「編集」→ 名前を変える → 既存品目名を送信 | 「すでにあります」でセッション継続。別名なら成功 |
| 13 | フロー途中で「キャンセル」 | 「キャンセルしました」で中断 |
| 14 | 「こんにちは」 | フォールバック(ヘルプ誘導)が返る |
| 15 | Notion画面で品目名を直接変更 → LINEで「在庫」 | 変更後の名前で表示される(Notion編集が反映: R-05) |
| 16 | Bの端末でBotをブロック | ユーザーDBのBが「無効」になる |
| 17 | ブロック中にAが「なくなった」 | Bに通知が飛ばない(エラーにもならない) |
| 18 | Bがブロック解除(再フォロー) | Bが「有効」に戻る。行は増えない |
| 19 | 5分放置したセッション(新規登録の品名待ち)にテキスト送信 | 通常コマンドとして処理される(セッション失効) |
| 20 | スタンプを送る | 無反応(エラーが出ない) |

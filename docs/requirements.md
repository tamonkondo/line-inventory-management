# 家庭内在庫管理システム 要件定義書

- **ドキュメント種別**: 要件定義書（確定版 v1.0 ＋ v1.1 追加要望ドラフト）
- **作成日**: 2026-07-10
- **最終更新**: 2026-07-10（「11. v1.1 追加機能要望」を追記）
- **ステータス**: v1.0 は確定（「9. 決定事項ログ」参照）。v1.1 はドラフト（「11.5 未確定事項」に論点あり）

---

## 1. 目的・背景

自宅にある洗剤・食品などの消耗品／在庫を、家族や同居人など複数人で共有して管理できる仕組みを構築する。

現状は「気づいたら切れていた」「二重に買ってしまった」といった課題が想定される。これを、

- **在庫データを Notion に一元管理**
- **日常的な操作は LINE Bot（トーク＆リッチメニュー）から**
- **不足品は在庫が下限を下回った時点で即時通知**

することで解消する。専用アプリを新規インストールさせず、普段使いの LINE 上で完結させることを狙いとする。

---

## 2. スコープ

### 2.1 対象（In Scope）

- 在庫の登録・参照・更新・消費（減算）・削除
- カテゴリ（洗剤 / 食品 など）ごとの在庫分類・絞り込み
- LINE Bot による在庫確認・操作
- リッチメニューからの主要操作の導線（「在庫確認」「不足一覧」等）
- 在庫が下限（しきい値）を下回った時点での**即時通知**
- Bot 利用ユーザーの登録・管理（家族・同居人の追加）
- Notion をデータストアとした GAS（Google Apps Script）による連携基盤

### 2.2 対象外（Out of Scope、初期リリースでは実施しない）

- ECサイトとの連携・自動発注
- バーコード／レシートのスキャン読み取り（将来拡張候補）
- 賞味期限のOCR自動取得・期限切れ通知（DB項目としては保持するが通知は将来拡張）
- **在庫不足の定期通知**（今回は即時通知のみを採用。将来拡張候補）
- 金額・家計簿としての集計機能
- Web管理画面（管理は当面 Notion 画面を直接利用）

## 3. 利用者（ロール）

**全員同権限**を採用する。ロールによる機能制限は設けず、Bot を友だち追加した全ユーザーが同じ操作を行える。

| 区分 | 説明 | 操作範囲 |
| --- | --- | --- |
| ユーザー | 家族・同居人。Bot を友だち追加した人全員 | 在庫の確認・追加・消費・更新・削除、通知受信、（実質的に）他ユーザーの参加も友だち追加で成立 |
| （システム） | GAS（Webhook処理） | 在庫操作の受付・不足判定・即時通知配信 |

> ロール区分（Owner/Member）は設けない。将来的に権限分離が必要になった場合は、ユーザーDBに Role プロパティを追加して拡張する（拡張余地として設計上残す）。

## 4. システム構成

### 4.1 全体構成

```
   ┌─────────────┐       Webhook (HTTPS)      ┌──────────────────────┐
   │   LINE       │ ─────────────────────────▶ │  GAS Web App          │
   │  （ユーザー） │ ◀───────────────────────── │  （doPost / doGet）    │
   └─────────────┘   Reply / Push (Messaging   └───────────┬──────────┘
                          API)                             │ Notion API (REST)
                                                           ▼
                                                    ┌──────────────────┐
                                                    │   Notion DB群      │
                                                    │ ・在庫DB           │
                                                    │ ・ユーザーDB       │
                                                    │ （・操作ログDB=将来）│
                                                    └──────────────────┘
```

- **通知は「操作起点の即時通知」**。在庫を減らす／更新する操作の結果、数量がしきい値以下になった時点で GAS が Push 通知を送る。
- 定期通知（時間主導トリガー）は今回採用しないため、上図に定期バッチ経路は含めない。将来「賞味期限通知」等を追加する際にトリガーを導入する。

### 4.2 コンポーネント

| コンポーネント | 技術 | 役割 |
| --- | --- | --- |
| フロント（UI） | LINE（トーク・リッチメニュー） | ユーザー入力／表示 |
| アプリ層 | GAS（Web App） | Webhook 受信、コマンド解釈、Notion 操作、返信、不足判定・即時通知 |
| データストア | Notion（複数DB） | 在庫・ユーザー（・将来ログ）の永続化 |
| 外部API | LINE Messaging API / Notion API | 送受信・データCRUD |

### 4.3 なぜこの構成か

- **GAS**: サーバー常駐不要・無料枠・LINE Webhook の受け口（HTTPS エンドポイント）を無料で用意できる。
- **Notion**: 非エンジニアでも画面から直接データを編集でき、DBとしても API 経由で操作可能。
- **LINE**: 追加インストール不要。リッチメニューで操作導線を固定できる。

## 5. データモデル（Notion DB設計）

**単一の在庫DB＋カテゴリ属性**方式を採用する。カテゴリごとの物理DB分割は行わない（集計・通知・検索を単純化するため）。

### 5.1 在庫DB（Inventory）※メイン

| プロパティ | 型 | 説明 |
| --- | --- | --- |
| 品名（Name） | Title | 例: 食器用洗剤 |
| カテゴリ（Category） | **Select** | 洗剤 / 食品 / 日用品 など（Selectで分類。DBは分割しない） |
| 数量（Quantity） | Number | 現在の在庫数 |
| 単位（Unit） | Select | 個 / 本 / 袋 / g など |
| 下限しきい値（Threshold） | Number | この値以下で「不足」判定 |
| 状態（Status） | Formula | 数量としきい値から自動判定（十分 / 残りわずか / 不足） |
| 保管場所（Location） | Select / Text | 洗面所 / パントリー など（任意） |
| 賞味期限（ExpiryDate） | Date | 食品向け（任意。項目は保持、期限切れ通知は将来拡張） |
| 最終更新日（UpdatedAt） | Last edited time | 自動 |
| 更新者（UpdatedBy） | Relation → ユーザーDB | 誰が最後に操作したか（任意） |

> Category を Select にすることで、カテゴリの追加・変更が Notion 画面から容易。将来カテゴリごとの既定しきい値等を持たせたくなれば、カテゴリDB＋Relation へ移行可能。

### 5.2 ユーザーDB（Users）

| プロパティ | 型 | 説明 |
| --- | --- | --- |
| 表示名（Name） | Title | LINE表示名（follow時に取得） |
| LINE User ID | Text | Messaging API の userId（一意キー） |
| ステータス（Status） | Select | 有効 / 無効（初期値は「有効」。友だち追加＝即有効） |
| 登録日（RegisteredAt） | Date | follow イベント発生日 |

> **Role プロパティは初期では持たない**（全員同権限のため）。将来の権限分離に備え、追加しやすい構造としておく。

### 5.3 操作ログDB（Logs）※将来拡張（P5）

「誰がいつ何を追加／消費したか」を追跡するためのDB。初期リリースでは作成しない。将来、履歴確認や通知の説明責任が必要になった段階で追加する。

| プロパティ | 型 | 説明 |
| --- | --- | --- |
| 日時 | Date | |
| 操作者 | Relation → Users | |
| 対象品目 | Relation → Inventory | |
| 操作種別 | Select | 追加 / 消費 / 更新 / 削除 |
| 増減量 | Number | |

## 6. 機能要件

### 6.1 在庫確認

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-01 | 在庫一覧表示 | リッチメニュー「在庫確認」で全在庫を状態付きで表示 |
| F-02 | カテゴリ別表示 | 洗剤 / 食品 などカテゴリで絞り込み表示 |
| F-03 | 不足一覧表示 | **リッチメニュー「不足一覧」** で、しきい値以下の品目のみをオンデマンド表示 |
| F-04 | 品名検索 | 「洗剤」などのキーワードで検索 |

- 表示形式は **Flex Message（カード）** を基本とし、品名・数量・状態を視認しやすくする。

### 6.2 在庫操作

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-05 | 在庫追加（新規品目） | 「追加 食器用洗剤 2本」等のコマンドまたはガイド付き入力 |
| F-06 | 在庫消費（減算） | 「消費 食器用洗剤 1」で数量を減らす |
| F-07 | 数量更新 | 数量を任意の値に上書き |
| F-08 | 品目削除 | 品目そのものを削除 |
| F-09 | しきい値設定 | 品目ごとの下限を設定・変更 |

- 入力方法は **(a) 定型コマンド文字列** と **(b) リッチメニュー起点のステップ入力（Postback）** の2系統を想定。誤操作防止のため削除・上書きは確認ステップを挟む。

### 6.3 通知（即時通知）

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-10 | 不足即時通知 | 在庫を減らす／更新する操作の結果、数量が **しきい値以下になった時点** で該当品目を通知 |
| F-11 | 通知先 | **有効ユーザー全員** へ LINE Push Message で配信 |
| F-12 | オンデマンド確認 | リッチメニュー「不足一覧」（F-03）でいつでも不足品を確認可能 |

- 定期（時間主導）通知は採用しない。通知は必ず「在庫を動かす操作」を起点に発火する。
- 連続操作での通知過多を避けるため、「しきい値を跨いで初めて不足になった時のみ通知」する等の抑制ルールを実装時に検討する。

### 6.4 ユーザー管理

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-13 | ユーザー自動登録 | Bot友だち追加（follow イベント）時に userId・表示名を取得し、ユーザーDBへ「有効」で自動登録 |
| F-14 | 他ユーザー追加 | **友だち追加で即利用可**。追加したい家族へ Bot の友だち追加URL／QRを共有するだけで参加完了（承認ステップなし） |
| F-15 | ユーザー無効化 | ブロック（unfollow イベント）検知、または手動でユーザーDBのステータスを「無効」に変更。無効ユーザーは通知対象外 |

- LINE では Bot が任意ユーザーを勝手に追加することはできない。**「対象者が Bot を友だち追加する」= 参加**、という流れで、承認制は設けない。

## 7. 非機能要件

| 区分 | 要件 |
| --- | --- |
| 可用性 | 個人利用前提。GAS/Notion/LINE 各サービスの稼働に依存 |
| 性能 | 応答は LINE Webhook のタイムアウト内（数秒）に返信。重い処理は分離 |
| 制約（GAS） | 実行時間・API呼び出し回数のクォータに留意。Notion APIは約3リクエスト/秒 |
| セキュリティ | LINE署名（X-Line-Signature）検証、Notion トークン等は GAS のスクリプトプロパティに保管しコード直書き禁止 |
| 保守性 | コマンド仕様・DBスキーマをドキュメント化。設定値は定数に集約 |
| コスト | 原則無料枠内（LINE 公式アカウント無料枠・GAS 無料・Notion 無料/既存プラン） |

## 8. 想定コマンド仕様

| 入力例 | 動作 |
| --- | --- |
| `在庫` / リッチメニュー「在庫確認」 | 全在庫一覧 |
| リッチメニュー「不足一覧」 / `不足` | しきい値以下の品目一覧 |
| `追加 食器用洗剤 2 本` | 新規または既存品目に +2 |
| `消費 食器用洗剤 1` | 数量 -1（結果がしきい値以下なら即時通知） |
| `検索 洗剤` | 品名に「洗剤」を含む品目 |
| `ヘルプ` | コマンド一覧を表示 |

> 自然文解釈まではせず、まずは「先頭キーワード＋引数」の簡易パースを想定。将来的にステップ式（Postback）UIへ寄せると誤入力が減る。

## 11. v1.1 追加機能要望（ドラフト）

v1.0 確定後に挙がった要望を整理する。確定した項目は順次「9. 決定事項ログ」へ移す。

### 11.1 要望一覧と対応方針

| ID | 要望 | 対応方針 | v1.0との関係 |
| --- | --- | --- | --- |

| R-04 | **商品に購入先カテゴリーを複数付ける** | 在庫DBに「購入先（Multi-select）」を追加（例: スーパー / ドラッグストア / Amazon） | 在庫DB（5.1）へのプロパティ追加。既存の「カテゴリ（品目分類）」とは別プロパティ |
| R-05 | **商品の編集は Notion で行う** | 品目のマスタ編集（カテゴリ・選択肢の管理等）は Notion 画面を正とする。ただし**画像・名前・購入先の3項目は LINE のやりとりでも変更可能**にする | v1.0 の方針（管理はNotion直接）を明文化＋LINE編集の対象を限定 |
| R-06 | **商品の追加は LINE で行う** | 新規品目の登録は LINE から（コマンドまたはステップ入力）。Notion側での手動追加も妨げない | F-05 の位置づけを明確化 |
| R-07 | **リッチメニュー構成** | 「11.3 リッチメニュー構成」参照 | P1 のリッチメニュー設置の具体化 |
| R-08 | **在庫は数量ではなく boolean で管理** | 「あるか / ないか」だけを持つ。数量（Quantity）・下限しきい値（Threshold）・状態Formula・消費コマンド（F-06〜07・09）は廃止 | v1.0 の 5.1・6.2・6.3 を置き換える確定方針 |
| R-09 | **保管場所・賞味期限を持たない** | 在庫DBから 保管場所（Location）・賞味期限（ExpiryDate）を削除。日用品中心の運用で不要と判断 | v1.0 の 5.1 から2プロパティを削除。賞味期限通知（将来拡張候補）もスコープ外にする |
| R-10 | **商品にメモを付けられる** | 在庫DBに「メモ（Rich text）」を追加。編集は Notion 画面から行い、LINE の品目カードに表示する（LINEからの編集対象には含めない: R-05 の3項目のまま） | 在庫DB（5.1）へのプロパティ追加 |
| R-11 | **「買った」も他ユーザーへ通知する** | 「買った」報告時に、報告者を除く有効ユーザー全員へ「【補充】〜」を即時通知（なくなった通知と同じ配信方式） | F-16 の通知を購入側にも拡張（実装書16） |
| R-12 | **通知に商品写真を添える** | なくなった/買った通知の際、品目に写真があればテキストに画像メッセージを添付 | 通知の改善（実装書16）。写真URLの1時間失効は許容 |
| R-13 | **新規登録でカテゴリ・購入先を選択式に** | Notionのプロパティ定義（Select/Multi-select）から選択肢を取得し、LINE上でボタン選択して登録。スキップ可・自由入力なし（選択肢管理はNotion: R-05維持） | 新規登録フローの拡張（実装書17） |

### 11.2 データモデルへの影響

**在庫DB（5.1）の変更**

R-08 により、数量ベースのプロパティを boolean へ置き換える。

| 変更 | プロパティ | 型 | 説明 |
| --- | --- | --- | --- |
| 廃止 | 数量（Quantity）/ 下限しきい値（Threshold）/ 状態（Status: Formula） | - | 数量管理をやめる |
| 追加 | **在庫あり（InStock）** | **Checkbox** | ON=在庫あり / OFF=在庫切れ。これが唯一の在庫状態（R-01/R-08） |
| 追加 | 写真（Photo） | Files & media | 商品写真。LINEから送信した画像を登録（R-03） |
| 追加 | 購入先（Stores） | **Multi-select** | 購入先カテゴリー。複数選択可（R-04） |
| 追加 | 最終購入日（LastPurchasedAt） | Rollup（購入履歴の購入日の最大値）または Date | 商品カードに表示（R-02） |
| 追加 | メモ（Memo） | Rich text | 自由記入。Notion画面で編集し、LINEの品目カードに表示（R-10） |
| 削除 | 保管場所（Location）/ 賞味期限（ExpiryDate） | - | v1.0 の任意プロパティを削除（R-09） |

**購入履歴DB（PurchaseHistory）※新設（R-02）**

| プロパティ | 型 | 説明 |
| --- | --- | --- |
| 名前（Name） | Title | 「品名 + 購入日」等の自動生成 |
| 対象品目（Item） | Relation → 在庫DB | |
| 購入日（PurchasedAt） | Date | |
| 購入先（Store） | Select | どこで買ったか（任意） |
| 記録者（RecordedBy） | Relation → ユーザーDB | 任意 |

> LINE での「買った」操作＝購入として扱い、購入履歴に1レコード追加するとともに在庫ありフラグをONに戻す。数量は管理しないため履歴にも持たない（必要ならメモ用に任意のNumberを追加可能）。

### 11.3 リッチメニュー構成（R-07）

| ボタン | 動作 |
| --- | --- |
| 在庫一覧 | 全品目を在庫あり/切れの状態付きで表示（F-01） |
| 不足一覧 | 在庫切れ（InStock=OFF）の品目のみ表示（F-03 ＋ R-01） |
| なくなった | 品目を選んで在庫切れを報告 → フラグOFF＋全員へ即時通知（F-16） |
| 買った | 品目を選んで在庫ありに戻す＋購入履歴を記録（F-17） |
| 新規登録 | 新しい品目を LINE から登録（R-06） |
| ヘルプ | コマンド一覧を表示 |

> 元の要望メモの「追加 → 既存追加」は「買った」、「不足 → 不足分」は「なくなった」報告＋「不足一覧」に対応。リッチメニューは2500x1686の6分割を想定。
